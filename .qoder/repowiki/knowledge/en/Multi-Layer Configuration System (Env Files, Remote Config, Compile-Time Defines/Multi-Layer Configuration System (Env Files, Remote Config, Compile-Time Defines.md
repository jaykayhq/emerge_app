The Emerge app implements a three-layer configuration system that resolves values through a strict priority order: Firebase Remote Config (production standard), .env files (development support), and compile-time `--dart-define` variables (fallback). This approach centralizes all runtime configuration in `lib/core/config/app_config.dart`, which exposes typed getters for environment detection, Firebase settings, security toggles, Sentry DSN, RevenueCat API keys, and ad unit IDs.

**Layer 1 — Firebase Remote Config**: The primary production source of truth. `RemoteConfigService` (in `lib/features/onboarding/data/services/remote_config_service.dart`) initializes with defaults for RevenueCat keys, onboarding archetypes/attributes/habit suggestions, and feature flags. Values are fetched asynchronously during app startup via `AppConfig.initializeRemoteConfig()`. Template parameters live in `remoteconfig.template.json` defining `revenuecat_google_api_key`, `revenuecat_apple_api_key`, and `free_habit_limit`.

**Layer 2 — .env files**: Loaded via `flutter_dotenv` at app initialization in `init_app.dart`. On non-web platforms, the code attempts to load `.env` and falls back gracefully if missing. Environment variables include `FIREBASE_API_KEY`, `FIREBASE_PROJECT_ID`, `FIREBASE_STORAGE_BUCKET`, `REVENUECAT_GOOGLE_API_KEY`, `REVENUECAT_APPLE_API_KEY`, `FLUTTER_ENV`, `APP_ENV`, `ENABLE_FIREBASE_APP_CHECK`, `ENABLE_SSL_PINNING`, and `ENABLE_RATE_LIMITING`. A template is provided in `.env.example`. Web builds skip dotenv loading entirely.

**Layer 3 — Compile-time defines**: Used as final fallbacks via `String.fromEnvironment()` for values like `FLUTTER_ENV`, `FIREBASE_API_KEY`, `SENTRY_DSN`, and deprecated RevenueCat keys marked `@Deprecated('Use Firebase Remote Config instead')`. Production validation enforces that `firebaseApiKey` must be non-empty when `isProduction` is true.

**Firebase Platform Configuration**: `firebase_options.dart` is auto-generated by FlutterFire CLI from `firebase.json`, providing per-platform `FirebaseOptions` (web/android/ios) with project ID `tradeflash-l2966`. The `firebase.json` also configures Firestore rules, Storage rules, Hosting headers, emulator ports, and Auth providers.

**Security & Validation**: `AppConfig.isValidConfig` validates required fields in production. `getRevenueCatApiKey()` throws an exception if test keys (`test_` prefix) are detected in production builds. PII redaction is enforced through `AppLogger` for all logging output.

**Initialization Order**: `initApp()` loads dotenv first, then initializes Firebase, App Check, Remote Config (async), AdMob with consent, Local Settings, and Notifications in parallel via `Future.wait`. Remote Config initialization is fire-and-forget to avoid blocking startup.
