Tests are organized into two top-level directories mirroring the production code structure:
- `test/` contains unit and widget tests split by concern: `core/` covers shared infrastructure (config, deletion, Drift DB, drift repositories, game loop, presentation widgets, router, services, sync engine), while `features/` mirrors each feature module with a data/domain/presentation layout matching the source. Each feature directory groups tests under `data/repositories`, `domain/entities|models|services`, and `presentation/providers|screens|widgets`.
- `integration_test/` holds end-to-end Flutter driver tests (`app_test.dart`, `onboarding_flow_test.dart`) and a dedicated Firebase Emulator test (`firebase_emulator_test.dart`) that connects to local Firestore/Auth/Functions emulators.
- Shared test infrastructure lives in `test/helpers/`: `widget_test_utils.dart` provides a `createScreenUnderTest` helper wrapping screens in `ProviderScope` + `MaterialApp`, and `helpers/mocks/` contains mock classes built with `mocktail` for auth, gamification, habits, onboarding, and social features.
- Drift-specific tests use an in-memory database via `core/drift/test_database.dart` which constructs `AppDatabase.withExecutor(NativeDatabase.memory())` so all DAO/repository tests run against a transient SQLite instance.
