Three independent entry points under `functions/src/` share a common purpose but differ in execution model:
- `seed.ts` is a standalone Node script (not a Cloud Function) that initializes the Firebase Admin SDK directly and runs `seedAll()` synchronously to batch-write `tribes`, `officialClubs`, and `challenges` collections.
- `seed_starter_habits.ts` and `seed_templates.ts` are HTTP-triggered Cloud Functions (`onRequest`) exposing endpoints `seedOnboardingCatalog` and `seedChallengeTemplates` respectively. Both guard access via a `Bearer <ADMIN_SECRET>` token checked against `process.env.ADMIN_SECRET`, then write their respective catalog arrays into `starter_habit_blueprints`/`interest_catalog` and `challengeTemplates` collections using Firestore batches.
- Data is organized as module-level constant arrays (`tribes`, `challenges`, `officialClubs`, `STARTER_HABIT_BLUEPRINTS`, `INTEREST_CATALOG`, `TEMPLATES`) that serve as the single source of truth for each collection. Each seeding function iterates its array, constructs a `db.batch()`, calls `batch.set(ref, { ...entry, createdAt/serverTimestamp })`, and commits atomically.
- Dependency direction is one-way: these files depend only on `firebase-admin` and `firebase-functions/v2/https`; they do not import other application modules.
