The module is split into two TypeScript sources compiled to the same `functions/lib/index.js` bundle. `src/index.ts` is the single deployment entry: it calls `setGlobalOptions` once (maxInstances=5, region us-central1, 256MiB/0.1 CPU), initializes the Firebase Admin SDK singleton, then exports multiple function handlers — callable HTTPS functions (`getAuraInsight`, `getGroqCoachAdvice`) built with `onCall`, scheduled cron jobs (`applyDailyDecayScheduled`, `applyDailyMomentumDecay`, `applyDailyTribeRecalculation`) via `onSchedule`, and re-exports sub-modules through `export * from` statements. `src/rateLimiter.ts` is a standalone Firestore trigger (`onDocumentCreated` on `users/{userId}/habits/{habitId}/completions/{completionId}`) that enforces a per-user-per-habit daily cap of 50 completions by querying recent timestamps and flagging users via custom claims plus a `security_logs` collection. The compiled `lib/index.js` mirrors this structure, using `__exportStar` to re-export each sub-module including `rateLimiter`. Dependency direction is one-way: `index.ts` imports business logic modules but `rateLimiter.ts` only depends on `firebase-functions/v2/firestore` and `firebase-admin`.
