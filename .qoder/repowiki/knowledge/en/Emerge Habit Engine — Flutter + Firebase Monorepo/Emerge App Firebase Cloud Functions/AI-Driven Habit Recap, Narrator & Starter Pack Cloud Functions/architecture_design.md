Three independent Firebase Functions v2 HTTPS callables, each exported as a single `onCall` handler:
- `ai_recap.ts` (`generateAiRecap`) — premium-gated: reads `user_stats`, `habits`, and `user_activity` collections over a configurable date window, computes per-habit velocity, auto-upgrades difficulty when completion rate exceeds 0.8/day, calls the Groq OpenAI-compatible chat endpoint for an identity-first insight, then writes the recap to both `user_stats/{uid}/recaps` and a global `weekly_recaps` collection.
- `narrator.ts` (`fillNarratorSlots`) — trigger-dispatched slot filler: a `buildPrompt` switch maps nine trigger types to typed prompts, `callGroq` hits Groq with `llama-3.1-8b-instant` and JSON-object response format, and results are merged with a `fallbackSlots` static table keyed by trigger so the function always returns content even when Groq is down.
- `create_starter_pack.ts` (`createStarterPack`) — server-authoritative habit creator: validates `blueprintIds` against the `starter_habit_blueprints` catalog via `db.getAll`, strips any client-supplied `identityTags` and stamps only trusted tags (`onboarding`, `blueprint:<id>`), writes up to three habits in individual `set` calls, and derives a headline attribute from the most common one.

All three use `firebase-functions/v2/https` for auth enforcement (`request.auth.uid`), `firebase-admin` Firestore for data access, and read `GROQ_API_KEY` from secrets/environment. There is no shared library between them; each file is self-contained and stateless except for Firestore reads/writes.
