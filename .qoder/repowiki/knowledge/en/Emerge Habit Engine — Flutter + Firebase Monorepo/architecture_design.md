The root orchestrates four runtime layers through Firebase tooling and Dart/Node build pipelines: (1) the Flutter app (`pubspec.yaml`) declares all UI, state (Riverpod), navigation (go_router), persistence (Drift/SQLite), and Firebase SDKs; (2) `firebase.json` binds Firestore rules, Storage rules, Remote Config templates, Hosting rewrites, emulator ports, and Flutter platform configs to a single project `tradeflash-l2966`; (3) the `functions/` directory holds Gen 2 Node.js 22 Cloud Functions with a predeploy `npm run build`, invoked by the Flutter app via `cloud_functions` package; (4) shared static resources live under `assets/` and are referenced both by Flutter's asset manifest and Hosting headers. Development is unified through the Firebase emulators suite (Auth, Functions, Firestore, Hosting, Storage, UI) running on fixed ports, while CI/test artifacts, coverage reports, and patch files sit alongside source for quick iteration.
