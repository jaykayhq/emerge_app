The app follows a feature-sliced architecture under `lib/`: `core/` holds cross-cutting concerns (init bootstrap, config, router, theme, services, drift database/repositories, security, sync), while `features/` contains domain-scoped modules (auth, habits, social, gamification, monetization, onboarding, blueprints, world_map, timeline, ai, settings, profile). `main.dart` bootstraps via an `UncontrolledProviderScope` with a single `ProviderContainer`, initializes Firebase, AdMob consent, Crashlytics/Sentry, and defers heavy work (sync trigger, tribe seeding) to `addPostFrameCallback`. Routing is centralized in `core/router/router.dart` using GoRouter with a `StatefulShellRoute.indexedStack` for the bottom navigation (Timeline, World, Social, Profile) plus separate `/creator/*` routes. State is managed through Riverpod 3.x with `@riverpod` generators (`router.g.dart`), providers are consumed via `ref.watch`/`ref.listen`, and async data uses `AsyncValue`. Platform-specific code lives in `android/` (Kotlin MainActivity, widgets, plugins like ScreenTimePlugin) and `ios/` (Swift AppDelegate, Runner project), while `web/` provides PWA assets, service worker, and Drift WASM support. Configuration flows through `AppConfig` with a three-layer fallback: Firebase Remote Config → `.env` → compile-time `--dart-define`.
